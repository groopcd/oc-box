# 1.7 — workspace manager, native attachments and exit-history recovery

**Experimental development release, not stable manager acceptance.** The owner
approved publishing a channel-integrated successor of the earlier `5573965`
candidate on `devel`, with its incomplete dashboard validation disclosed below.
Stable `master`, v1.6.94 and its PyPI files remain unchanged. Check the
[GitHub release page](https://github.com/groopcd/oc-box/releases) for availability
and each publication's actual source identity.

Development versions are `1.7.N.dev0`, where N is the full Git commit count minus
the original stable baseline, 29. Resources retain `1.7.N.dev0+gHASH`, the full
commit and absolute count. A source change advances N; this publication is not
the exact old `1.7.110+g5573965` candidate. The final patch/hash are deliberately
not fixed in this document. Do not add a source/evidence commit between freezing
and publishing the validated successor.

## Next development update after v1.7.249.dev0

These changes are for the next `devel` prerelease, not features of the already
published `v1.7.249.dev0`. The earlier 1.7 release record and its validation
scopes remain below.

- **Quieter launcher, one history result.** A capable TTY shows one transient
  progress line; pipes and `TERM=dumb` no longer get routine stage start/done
  messages. Native OpenCode output, actionable warnings and prompts remain
  visible. Each history attempt reports one final result: saved, recovered after
  stop, partial, failed, empty or cleanup unverified. Recovery still warns about
  interrupted work and unconfirmed completion; neither history success nor
  cleanup is inferred from a client exit alone. The presentation does not change
  recovery eligibility or exit policy. Opt in to expanded launcher messages
  with `--lifecycle-diagnostics` for one invocation.
- **Read-only activity logs on the host.** `oc-box logs` defaults to the latest
  100 matching private entries at `info` or higher. Choose a severity threshold,
  workspace and limit, follow new entries, or emit one validated record per line
  with `--json`. `oc-box logs --path` shows the private journal pathname without
  opening it. Saved host policy can specify a private directory and bounded
  size, count, age and free-space retention; rotation and retention act only on
  append. Custom journals refuse unrecognized active data and never overwrite
  an occupied rotation destination. `--log-dir PATH` selects a private journal
  for one invocation without moving existing logs or changing the workspace
  registry.
- **Optional system journal mirror.** This is off by default. The private file
  stays primary: only successfully appended, validated activity events can be
  mirrored at native priorities. `start` (including implicit start), `reset`,
  `stop`, `sync`, `terminal` and `web` accept one-invocation `--journald` /
  `--no-journald`, `--log-dir PATH` and `--lifecycle-diagnostics`. In contrast,
  `oc-box logs --journald` explicitly reads the current user's mirror; it does
  not enable mirroring or silently fall back to private files.
- **Grouped help.** `oc-box --help` is a short command index. Use
  `oc-box start --help` or `oc-box logs --help` for the relevant options without
  resolving a workspace or touching launcher state. Implicit start and the
  legacy selector-first form still work.
- **Dashboard logs and controls.** Browse a sortable table or an unformatted
  **RAW** view of retained display records, with source, severity and literal
  search filters and a bounded **Copy all** action. The private source includes
  `debug`. **Load mirror** reads a separate same-user snapshot rather than merging
  it into ordinary logs. Rounded controls retain visible focus and keyboard
  operation. **Save Host Logging** can change the private directory
  and mirror choice separately from session-only settings; it does not migrate
  logs, and is unavailable in demo or read-only mode. Changing sources clears
  stale selections. An unavailable Podman target does not prevent the private
  journal from refreshing.
- **Native clipboard relay recovery without input replay.** A well-formed
  ordinary paste above the 16 KiB pathname-capture limit passes through unchanged,
  with no import callbacks until its exact closing delimiter. Certain embedded
  control bytes in a recognized paste or CSI sequence also pass through without
  triggering an import; interception resumes only at an unambiguous frame end.
  Ambiguous framing still disables interception for the client. After
  `clipboard-unexpected-read`, only a later qualifying Ctrl+Y event can try
  again, and only if desktop helper reaping was verified. Success does not
  replenish the allowance. Another unexpected read failure or unverified helper
  cleanup disables clipboard importing; unverified staging also stops pathname
  and Kitty file imports for that client. No automatic retry, replay, restart or
  prompt submission is added.

See the [CLI reference](../cli.md#logs), [dashboard guide](../tui.md#5-logs)
and [clipboard host check](../host-clipboard-testing.md). These changes do not
establish new external-host, desktop/composer, system-journal or interactive
manager acceptance. Earlier results retain their original source identities.

## Highlights

- **Optional seven-tab Textual manager:** Status, Settings, Sessions, Terminals,
  Logs, Storage and Backup/restore, separate from OpenCode's native conversation UI. It has compact
  aligned diagnostics, fixed-scale histories, explicit session connections,
  source-specific archive/delete actions, private favorites, bounded logs and
  session-only preferences. Browsing never starts, resets, syncs or unlocks a
  workspace. See the [detailed manager notes](tui-v1.md).
- **Scoped storage and encrypted backups:** separate host session-tree, selected
  workspace and all-workspace inventories, with explicit single-target reviews.
  Full/portable `.ocbox` backups and native `.ocsession` history use existing
   masked TTY-backed prompts, no-overwrite archives and fresh-ID restores.
  Workspace removal preserves project files and host history; there is no whole
  host database replacement/wipe, bulk purge or shared-cache pruning.
- **Visible session feedback:** connection loading/cancellation states and
  reason-specific deletion notices distinguish preflight refusals, uncertain
  mutation acknowledgements and completed mutations followed by failed refresh.
- **Explicit clipboard controls:** selectable visible text, completed-user-
  selection auto-copy, selection/screen-copy shortcuts and in-app Paste copied. Programmatic
  selection, refresh, focus and container OSC requests do not copy. Clipboard
  text and terminal output are not journaled.
- **Experimental embedded native session terminal:** validated attachment and
  visible leases reuse the existing persistent session PTY, with resize and
  Ctrl-] detach. This is not a replacement container shell or a full xterm.
- **Temporary live host-file tools:** `oc-box share PATH` gives an existing V2
  workspace read-only listing, UTF-8 reads and PNG/JPEG/GIF/WebP image reads.
  Access is live rather than a copied snapshot, with no mount, restart, host
  listener or saved MCP entry. A host warning and typed confirmation are
  required unless the operator explicitly supplies `--acknowledge-risk`.
- **Archived-root resume behavior:** archived V2 roots remain synchronized and
  retained, but are not automatic resume targets. Archiving every root can cause
  the next owning start to create a fresh conversation; unarchiving a root makes
  it eligible again. This does not delete the original conversations.
- **Guarded exit-history recovery:** eligible V2 version-specific job timeouts can save
  checked persisted-history snapshots after a verified whole-container stop.
  oc-box temporarily restarts the same existing container for one isolated reader,
  without resuming requested work or refreshing credentials. Raw client failures
  remain nonzero; a clean client can succeed only after fully verified archival,
  recovery cleanup and final stop. Interrupted-work/unconfirmed-completion warnings
  remain; this does not repair native job state.
- **Current stable fixes retained:** anonymous-memory capture works on supported
  Linux systems even when an older uv-managed Python lacks `os.memfd_create`,
  using the libc binding without disk-backed fallback. The temporary Ubuntu CI
  APT bootstrap repair retains signed packages, TLS and freshness checks and
  does not alter production dependency mappings or host DNS.
- **Published update channels:** stable remains the default; explicit
  `upgrade --devel` remembers the development choice and `--stable` switches
  back. GitHub selects verified published releases, not moving branch HEAD.
  Package updates delegate only to the verified owning tool/environment, never
  the GitHub installer. Preview checks save nothing. See the
   [channel guide](../update-channels.md).

### Combined dashboard, history and attachment update

This development successor combines the approved card-dashboard work, the
retained-subagent recovery correction and native/browser attachment support.
It is a new development publication, not stable promotion or an extension of
earlier exact-source host acceptance.

- **Card dashboard:** responsive navy/cyan resource cards, workspace context and
  inspector, inline session-only settings, compact switches and larger input-clear
  hit targets. No resource-control RPCs, persistent dashboard settings, new
  telemetry or weakened private-input/operation reviews are introduced.
- **Retained-subagent history:** the exact native 2.3.0 fallback described below
  preserves pending-job refusal in a live owner, then permits checked persisted
  history only after verified shutdown. The outcome policy below preserves
  warnings and raw client failures; jobs are not resumed, acknowledged or declared
  completed.
- **Native TUI host images/PDFs:** supported direct Konsole/Kitty clients enable
  importing by default per workspace. `--no-host-drop` saves an opt-out;
  `--host-drop` saves enabled and strictly requires compatibility. Automatic mode
  skips unsupported clients rather than preventing ordinary startup.
  `oc-box preferences --host-drop off` changes only future-client policy without
  opening another client, unlocking credentials or touching native configuration.
  Existing clients do not live-toggle.
- **Shared web tabstrip:** one first-party shell shows verified open TUI roots,
  including idle conversations, around one unmodified native iframe. Fresh
  cooperative TUI reports select the exact owning-TUI conversation, including
  children, while root highlighting remains separate. Explicit `web --session`
  wins; unavailable, expired or ambiguous reports do not become activity/order
  guesses. Older owners require explicit selection until a normal new owning
  startup installs the helper. Native read-only children remain read-only.
- **Optional browser attachments:** `oc-box web --attachments` adds trusted
  browser File drops and a chooser to that same iframe. The native composer owns
  drafts and Send; there is no automatic prompt submission. The separate
  confirmation-based `attach --broker` remains available.

**Disclosure change:** a qualifying complete image/PDF pathname paste anywhere
in an importing-enabled native TUI authorizes capture without per-file
confirmation. This is not proof of a physical drag or composer focus. Save
importing disabled when that policy is inappropriate. Konsole remains
pathname-paste-only, with unchanged child output and no OSC 72 probes. Only the
known Kitty profile reserves its audited structured-drop traffic.

Native TUI limits are 8 MiB/file, four files/16 MiB per batch and 32 files/64 MiB
per client. Browser limits are 20 MiB/file, eight files/40 MiB per drop.
PNG/JPEG/GIF/WebP/PDF are supported within their respective guards; DOCX conversion
is not provided. Model support varies. Native/browser staging, history,
provider processing, copies and backups can retain disclosed bytes; cleanup is
bounded best-effort, not recall or per-session filesystem isolation.

## Temporary sharing

Run from a second host terminal while the selected V2 workspace is running:

```sh
oc-box share ~/Pictures/Screenshots --project ~/devel/demo
```

Read the warning, type `share`, and ask OpenCode to use the uniquely named
server's `list_directory`, `read_file` or `read_image` tools. Paths are relative
to the shared root; `.` selects a single shared file. Keep the command open and
press Ctrl-C to stop further broker reads. This is tool access, not a path for
ordinary container shell/file tools. Existing containers require no reset.

**Read-only does not prevent disclosure.** Hidden files and future additions in
a selected folder are included. Shared data may reach model providers, history,
logs, backups or copies; disconnect cannot recall it. Other sessions at the same
workspace location can use the tools. Prefer one file or the narrowest folder.
Symlinks, hard-linked/special files, traversal, nested mounts and protected
application/credential/state paths refuse access. Directory lookup requires
Linux `openat2`; unsupported kernels/policies fail closed. Text/image/directory
bounds and root-replacement rules are in the [command reference](../cli.md#share).

Sharing uses an experimental native V2 API. Its independent source-pinned offline
fixture covers production transport, live updates, structured image delivery,
location confinement, close/reload removal and unrelated MCP preservation.
Separately, 37 reviewed scripted external-host checks passed on `5573965` with
native 2.2.6, including nested mounts and enforcing SELinux with source labels
unchanged. That evidence is not interactive UI acceptance, a security
certification, or an exact-source pass for the channel-integrated successor.

## Exit-history recovery

### Native 2.3.0 development backport

The development line now includes the audited native **2.3.0** recovery extension
from stable-line commits `328f83e` and `7f441b8`. Only the two recovery modules and
their focused regressions/native fixture are ported; unrelated stable runtime,
host fixtures, CI orchestration and dashboard changes are not merged.
That original backport supported exactly **2.2.6, 2.2.7 and 2.3.0**. The later
2.3.x compatibility amendment below changes current eligibility without
reclassifying the original native evidence.

Native 2.3.0 drains the old reload/cancelled-job case, but can retain a running
shell after producer termination. The native fixture therefore uses an actual
held shell and an ownership-checked, pidfd-bound local producer-stop/reap barrier,
then verifies unchanged durable jobs, schedules and transcripts through the same
isolated reader and real host archive/import checks. This is native/offline
coverage, not whole-container stop/restart or new integrated host acceptance.
The original live timeout, interrupted-work warning and all
scheduler/system-configuration guards remain unchanged. The later outcome-only
amendment below preserves raw client failures while distinguishing fully verified
archival from interrupted execution. No native job is repaired or deleted. The
[known dashboard acceptance limitations](#known-acceptance-limitations) remain in force.

### Retained-subagent timeout fallback

The recovery successor also handles an audited native **2.3.0** case: durable
subagent jobs can remain marked running after their original producer stops,
while a new process has no foreground activity. This is not established by
history size or a timeout phase alone. Diagnostics add known job-kind counts,
without identifiers or job descriptions.

The live wait still refuses pending jobs. After repeated qualifying observations,
normal owner closure and verified whole-container stop, the automatic path can
read checked persisted history through one isolated, unregistered reader. It
does not recursively launch ordinary `oc-box sync`, resume subagents, acknowledge
jobs or erase execution claims. Native 2.2.6/2.2.7 keep the shell-only profile;
image jobs and unsupported versions remain refused. The new 2.3.0 source and
destination guards validate durable job/recovery metadata before native history
processing, alongside the existing scheduler/configuration/ownership fences.

The native regression covers retained subagent jobs and unchanged durable state.
This is local synthetic/native coverage, not new external-host acceptance.
The original timeout/interruption warning remains under the later outcome
policy below. Earlier host reports below retain their exact historical source,
recorded exit statuses and scope; they do not accept this recovery successor.

### Verified archival outcome after a clean client exit

The approved shutdown change separates live readiness, archive completion and
the raw UI/client result. If the raw client exits `0`, an eligible live timeout
may still end with CLI exit `0` **only** after the existing guarded post-stop
reader completes all checked exports, host imports and independent native
verification, followed by successful recovery cleanup and a verified final stop.
Owning native TUI and web launches use the same policy.

The explicit warning remains: execution was interrupted and background completion
is unconfirmed; final results or completion notices may be missing. Actual client
failures, including exit `7` and cancellation, are preserved. Unknown client
status, pending/partial history, sync/recovery failures and failed/uncertain
cleanup remain nonzero. Whenever history sync, recovery or cleanup fails, the
existing guidance to retry `oc-box sync` remains.

The automatic path already uses the same checked `sync_sessions` implementation
as manual sync. It adds no recursive CLI call, ordinary runtime preparation,
vault unlock, configuration/plugin/credential refresh or job/input
acknowledgement. Eligibility is shell-only on native
2.2.6/2.2.7 and shell/subagent on stable 2.3.x under the compatibility amendment
below; there is no job-age/status exemption,
job cleanup or global permission autoaccept.

The 30-second grace is oc-box's live-readiness wait, not a native archive-copy
timeout, and is unchanged. Automatic exit may spend that grace before checked
archive copying; manual sync omits the original owner's live wait but still does
its ordinary preparation and checked archival work. Progress labels distinguish
waiting from actual copying, and fully successful recovery is not summarized as
an overall sync failure. A small aggregate summary reports sessions, exported,
unchanged, updated and pending counts, elapsed time and a fixed source mode
(`post-stop-reader`, `private-endpoint` or `standalone`), never IDs, titles,
argv, environment values, native errors or model values.

Validation for this narrow change is limited to focused local fake-boundary
policy/output cases; no new native or external-host pass is claimed here.
Historical `[0,1]` owner exits remain historical, not reclassified successes.
The new source/outcome policy requires separately scoped formal acceptance before
any later release; this amendment does not authorize publication or replay of
retained fixtures.

### Guarded compatibility across stable native 2.3.x

The original `cb1e299` outcome correction could not run its fallback on native
2.3.2: both capture and retained-subagent routing still selected only 2.3.0.
The compatibility amendment uses one shared storage-profile selector for every
canonical stable `2.3.N` version, not a growing patch allowlist. It retains exact
2.2.6/2.2.7 shell-only behavior and refuses prereleases, modified/malformed
identities and unknown minor/major series. Unsupported native versions now warn
before the owning client opens instead of first revealing this limit at exit.
Detected schema/metadata and activity-response incompatibilities also print
fixed-category guidance: check for an oc-box update first, update an older
OpenCode to a supported release when appropriate, and report the refusal if both
are current. Preserve workspace/history rather than resetting or downgrading
state to bypass the check. These are compatibility refusals, not declarations
that upgrading necessarily repairs every unsupported state.

All 2.3.x patches select the existing strict job/recovery metadata, filesystem,
deadline, scheduler and system-configuration checks on both source and destination.
The profile recognizes known `schedule` and newer `automation` column layouts,
requires exactly one of them, and refuses every scheduler row before native
startup regardless of status or WAL placement. The 2.3.0 binary is refused on an
automation-layout store. Native 2.3.1/2.3.2's optional subagent `outstanding`
metadata is explicitly bounded and validated for known shell/subagent references,
not silently discarded. Unknown/nested, image and Code Mode forms remain refused.
Image/unknown jobs, unknown forms, legacy background state and incompatible
schemas still refuse before native history processing. Actual executable probes
must match the captured exact patch version on both sides. A matching series
does not permit a different host/container patch or authorize normal managed
restart continuity, recursive manual-sync preparation or background execution.
A compatible future patch needs no new allowlist entry while these contract
checks hold. Matching schemas alone cannot prove unknown native startup behavior;
unrecognized minor/major series still require separate qualification.
The guards check column layouts, not a complete fingerprint of defaults, triggers,
indexes or foreign keys; future schema-preserving startup behavior remains an
assumption, not a proven non-execution guarantee.

The unchanged 30-second live grace and checked post-stop archival/outcome rules
still apply. This is recovery compatibility only, not a full-history performance
fix or an expansion of unrelated native UI/attachment or quiet-source features.
The focused native regression accepts a selected stable 2.3.x executable; CI
retains 2.3.0 and follows the latest stable 2.3 patch (2.3.2 when this amendment

### Post-stop source transport reuse

The performance amendment reuses one private Python export helper per guarded
post-stop sync pass instead of a fresh container/Python invocation for every
source operation. Complete inventory, the same full checked exports, pending
session isolation, archive bytes/digests and independent destination verification
remain intact. Requests are serial and individually admitted against stop intent;
there is no bulk session queue, new native service, automatic worker restart,
destination writer reuse or global readiness waiver.

The helper has bounded private framing and cleanup, is reaped before final
success, and refuses extra output even after stdin EOF. The 30-second grace,
snapshot budget and normal retry guidance are unchanged. Ordinary live/manual
sync and V1 remain on their previous transports.

A compact fake-loopback observation reduced the 136-small-export command
component from 22.861 to 0.240 seconds with identical HTTP checks and bytes.
This excludes actual Podman/native/destination costs and is not a prediction for
the operator's larger real-project history. Focused transport regressions and the
existing small native 2.3.2 case passed; final host timing remains unverified.
This amendment does not itself authorize another publication.

### Recovery behavior and earlier evidence

Native OpenCode can retain background-shell jobs after a location reload, even
when no foreground session is running. A retained job may still appear running
after reopening. These rows remain blocking in the live owner; neither native
export success nor job age proves that work completed.

The earlier shell-only implementation kept an eligible activity timeout nonzero
and, after clients detached and the owner closed normally, verified a full stop of
the same existing container. If no explicit stop request superseded recovery, it
permitted one bounded history-only restart, read persisted sessions through one
isolated private reader, verified their host archive imports, and stopped the
container again. It created no replacement container or volume and performed no
normal runtime/configuration/auth preparation, vault unlock or requested
model/tool execution.

**The earlier accepted sources returned nonzero even after saving history.**
Their recorded outcomes remain unchanged; the later clean-client outcome policy
above does not relabel them. Execution was interrupted and completion notices or
final results may be missing. Running projected messages, unfinished tails,
changing exports and unsafe stores remain refused. No job is deleted, rewritten
or declared completed, and the reader does not invent a missing notice. This is
persisted-history synchronization, not a byte-read-only database backup or
automatic work replay.

Explicit `oc-box stop` participates in private stop-intent/admission coordination
so an ordered successful stop is not undone by recovery. An indeterminate start
retains an uncertainty fence instead of a successful-stop claim. Recovery is
conservative: version/identity, passive-container, scheduler and system-config
guards can leave history pending for manual action. No new user flag is required.
See the [command reference](../cli.md#web--browser-interface) for detailed
conditions and the [test strategy](../testing.md#reviewed-focused-recovery-host-acceptance)
for exact evidence identities and coverage limits.

The fix's clean runtime `d736bc1` (`1.7.86+gd736bc1`, count 115), external runner
`60df669` and native 2.2.6 have 60 reviewed scripted synthetic host checks: 42
baseline, 12 recovery snapshot and six stop-cancellation checks. All 44 audited
runtime/donor hashes match Git. These are source-qualified component results, not
acceptance of a later integrated 1.7 release. Native 2.2.7/2.3.0 reader coverage is
offline-only; the earlier failed recovery-oracle attempt remains failed evidence.

## Installation and upgrades after publication

Ordinary installations still default to stable, which does not include this
manager. For a published development package, explicitly allow prereleases:

```sh
uv tool install --prerelease allow 'oc-box[tui,vault]'
# Or: pipx install --pip-args='--pre' 'oc-box[tui,vault]'
oc-box tui --read-only
```

Use `[tui]` without `[vault]` if appropriate. Ordinary CLI/sharing imports remain
stdlib-only. A channel-aware GitHub bootstrap can explicitly select
`--devel --with-tui --with-vault`; supported optional extras survive updates.
Current channel-aware installations can use `oc-box upgrade --devel`, including
package installations with verified ownership. Old pre-channel 1.7 launchers
need the bootstrap instead of unsupported new flags. See
[update channels](../update-channels.md) for all bootstrap/package examples.

The version-series/channel change itself needs no workspace reset or database
migration. An explicit return to an older stable launcher warns and changes only
program files; it does not roll back workspace/session state.
