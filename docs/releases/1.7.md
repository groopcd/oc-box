# 1.7 — workspace manager, live host-file tools and exit-history recovery

**Release notes and publication checklist for the 1.7 rollout. Development-branch
contents and component test results are not proof of a published stable release.
Use the [GitHub release page](https://github.com/groopcd/oc-box/releases) for
availability and the accepted source identity. Publication requires the final
integrated-candidate gates below.**

The series is `1.7.N`, where N is the full Git commit count minus the original
stable baseline, 29. It does not restart at `1.7.0`. Each release's patch, source
hash and count are determined by its committed, frozen integrated candidate.
Do not add a source/evidence commit between acceptance and tagging that source.

## Highlights

- **Optional five-tab Textual manager:** Status, Settings, Sessions, Terminals
  and Logs, separate from OpenCode's native conversation UI. It has compact
  aligned diagnostics, fixed-scale histories, explicit session connections,
  source-specific archive/delete actions, private favorites, bounded logs and
  session-only preferences. Browsing never starts, resets, syncs or unlocks a
  workspace. See the [detailed manager notes](tui-v1.md).
- **Explicit clipboard controls:** selectable visible text, completed-user-
  selection auto-copy, Copy/Copy view and in-app Paste copied. Programmatic
  selection, refresh, focus and container OSC requests do not copy. Clipboard
  text and terminal output are not journaled.
- **Experimental embedded native session terminal:** validated attachment and
  visible leases reuse the existing persistent session PTY, with resize and
  Ctrl-] detach. This is not a replacement container shell or a full xterm.
- **Temporary live host-file tools:** `oc-box share PATH` gives an existing V2
  workspace read-only listing, UTF-8 reads and PNG/JPEG/GIF/WebP image reads.
  Access is live rather than a copied snapshot, with no mount, restart, host
  listener or saved MCP entry. A host warning and typed confirmation are
  required unless the operator explicitly supplies `--acknowledge-risk`.
- **Archived-root resume behavior:** archived V2 roots remain synchronized and
  retained, but are not automatic resume targets. Archiving every root can cause
  the next owning start to create a fresh conversation; unarchiving a root makes
  it eligible again. This does not delete the original conversations.
- **Guarded exit-history recovery:** eligible V2 shell-only timeouts can save
  checked persisted-history snapshots after a verified whole-container stop.
  oc-box temporarily restarts the same existing container for one isolated reader,
  without resuming requested work or refreshing credentials. The original nonzero
  result and interrupted-work warning remain; this does not repair native job state.
- **Current stable fixes retained:** anonymous-memory capture works on supported
  Linux systems even when an older uv-managed Python lacks `os.memfd_create`,
  using the libc binding without disk-backed fallback. The temporary Ubuntu CI
  APT bootstrap repair retains signed packages, TLS and freshness checks and
  does not alter production dependency mappings or host DNS.

Resource editing, quotas, live resize controls and storage moves are not added.
Mainline OpenCode remains unmodified; V1 launcher/history and V2 private owners,
credential handling, MCPs, formatters and plugin compatibility remain supported.

## Temporary sharing

Run from a second host terminal while the selected V2 workspace is running:

```sh
oc-box share ~/Pictures/Screenshots --project ~/devel/demo
```

Read the warning, type `share`, and ask OpenCode to use the uniquely named
server's `list_directory`, `read_file` or `read_image` tools. Paths are relative
to the shared root; `.` selects a single shared file. Keep the command open and
press Ctrl-C to stop further broker reads. This is tool access, not a path for
ordinary container shell/file tools. Existing containers require no reset.

**Read-only does not prevent disclosure.** Hidden files and future additions in
a selected folder are included. Shared data may reach model providers, history,
logs, backups or copies; disconnect cannot recall it. Other sessions at the same
workspace location can use the tools. Prefer one file or the narrowest folder.
Symlinks, hard-linked/special files, traversal, nested mounts and protected
application/credential/state paths refuse access. Directory lookup requires
Linux `openat2`; unsupported kernels/policies fail closed. Text/image/directory
bounds and root-replacement rules are in the [command reference](../cli.md#share).

Sharing uses an experimental native V2 API. Its independent source-pinned offline
fixture covers production transport, live updates, structured image delivery,
location confinement, close/reload removal and unrelated MCP preservation. This
is not rootless-Podman, enforcing-SELinux or interactive host acceptance.

## Exit-history recovery

Native OpenCode can retain background-shell jobs after a location reload, even
when no foreground session is running. A retained job may still appear running
after reopening. These rows remain blocking in the live owner; neither native
export success nor job age proves that work completed.

When a supported V2 owner reaches an eligible shell-only activity timeout, oc-box
keeps that failure and, after clients detach and the owner closes normally,
verifies a full stop of the same existing container. If no explicit stop request
supersedes recovery, it permits one bounded
history-only restart, reads persisted sessions through one isolated private reader,
verifies their host archive imports, and stops the container again. It creates no
replacement container or volume and performs no normal runtime/configuration/auth
preparation, vault unlock or requested model/tool execution.

**History can be recovered while the command still exits nonzero.** That warning
is intentional: execution was interrupted and completion notices or final results
may be missing. Running projected messages, unfinished tails, changing exports and
unsafe stores remain refused. No job is deleted, rewritten or declared completed,
and the reader does not invent a missing notice. This is persisted-history
synchronization, not a byte-read-only database backup or automatic work replay.

Explicit `oc-box stop` participates in private stop-intent/admission coordination
so an ordered successful stop is not undone by recovery. An indeterminate start
retains an uncertainty fence instead of a successful-stop claim. Recovery is
conservative: version/identity, passive-container, scheduler and system-config
guards can leave history pending for manual action. No new user flag is required.
See the [command reference](../cli.md#web--browser-interface) for detailed
conditions and the [test strategy](../testing.md#reviewed-focused-recovery-host-acceptance)
for exact evidence identities and coverage limits.

The fix's clean runtime `d736bc1` (`1.7.86+gd736bc1`, count 115), external runner
`60df669` and native 2.2.6 have 60 reviewed scripted synthetic host checks: 42
baseline, 12 recovery snapshot and six stop-cancellation checks. All 44 audited
runtime/donor hashes match Git. These are source-qualified component results, not
acceptance of a later integrated 1.7 release. Native 2.2.7 reader coverage is
offline-only; the earlier failed recovery-oracle attempt remains failed evidence.

## Installation and upgrades after publication

These commands apply **only after a stable 1.7 release has passed acceptance and
been published**. Check the release page for availability; a development branch
or passing component report is not a published PyPI package:

```sh
uv tool install 'oc-box[tui,vault]'
# Or: pipx install 'oc-box[tui,vault]'
oc-box tui --read-only
```

Use `[tui]` without `[vault]` if appropriate. Ordinary CLI/sharing imports remain
stdlib-only. GitHub installations can select `--with-tui` and `--with-vault`;
existing opt-ins survive GitHub upgrades. Python-package installations upgrade
through their owning tool manager, not `oc-box upgrade`.

The version-series change itself needs no workspace reset or database migration.
Older installed 0.1/1.0/1.5/1.6 builds retain their original embedded identity
until upgraded. Full-history commit count and the original patch baseline remain
intact, and package resources retain the full `+gHASH` source identity.
