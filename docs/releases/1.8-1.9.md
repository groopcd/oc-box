# Stable 1.8 and development 1.9

[Documentation hub](../README.md) · [Get started](../getting-started.md) ·
[Update channels](../update-channels.md)

The initial `1.8` stable and `1.9` development releases share the product
features below. Stable is the default channel; use a published `1.9` `.dev0`
prerelease only when you want the development channel. The oc-box channel does
not select your OpenCode major. Workspaces continue to use the exact installed
host OpenCode version. The primary guides cover 2.x; legacy
[OpenCode 1.x workflows](../legacy/README.md) remain supported separately.

## What stable users gain since 1.6

| Area | What changed | Start here |
| --- | --- | --- |
| Workspace manager | An optional seven-section Textual dashboard with live status, settings, scoped sessions, embedded native terminal, logs, storage, and guarded backup/restore. It is not a replacement chat client. | [Dashboard guide](../tui.md) |
| Concurrent clients | View a running native workspace in the TUI and browser while using its persistent session shell. Detach leaves that shell running; the owning launcher waits for attached clients before final synchronization and stop. | [Client workflows](../guides/clients.md) |
| Browser workspace | Opt in with `oc-box web --workspace-layout`. Studio, Dashboard, Chat focus, and the read-only Workspace manager arrange one native OpenCode view. Verified open native TUI tabs and explicitly loaded workspace history are different lists. | [Browser workspace](../web-shell.md) |
| Live host files | `oc-box share` grants scoped read-only file and folder tools through a verified native client connection. It does not mount the source or grant container shell access. Consent is explicit; disconnect cannot recall data already read. | [Host file access](../guides/host-files.md) |
| Images, PDFs, and host opening | Native TUI path imports, opt-in Ctrl+Y clipboard imports, explicit image messages or approval brokers, and the optional browser file adapter have separate version, terminal, and consent limits. Experimental Ctrl-click opens only verified private copies on the host. | [Choose a transfer](../guides/host-files.md) |
| Encrypted data workflows | Review full and portable workspace backups, fresh stopped restores, encrypted native session-tree exports, and explicitly selected host settings. The dashboard uses masked private prompts and does not silently overwrite, start a restore, or grant old privileges. | [Backup and restore](../guides/backups.md) |
| History and recovery | Retain synchronized native history, including archived roots without automatically resuming them. Supported interrupted owners may archive persisted history after a verified stop; that does not prove a running job completed or make unsupported work recoverable. | [Workspace history](../guides/workspaces.md) |
| Startup and logs | Routine startup progress is quieter; the private activity journal and preparation log show fixed metadata. External container logs and journal mirroring are opt-in. Supported Kitty/Konsole profiles can show startup graphics; the normal fallback and the dashboard's centered cube are text. | [Command reference](../cli.md) |

These features do not add live resource-limit edits, a whole-host database
wipe, transparent host access, or a separate native web application. Read
[the security boundaries](../../SECURITY.md) before granting file or credential
access.

## What changes in development 1.9

For users already on the `1.7` development line, this release establishes the
odd-minor `1.9` prerelease series alongside stable `1.8`; it does not reintroduce
all the earlier dashboard features as new. The dashboard retains its centered
text cube. The opt-in live browser layout retains native one-use loopback
pairing and does not ship the experimental named-account or certificate setup.
The earlier `web tls` preparation/check commands and `doctor --feature
web-tls-local` are not part of this release's installed CLI.

Both channels fix an npm 10 managed-SDK failure in which a hoisted lock
generated during setup could be rejected by the subsequent clean install.
Managed resolution and installation now use the same shallow layout; the
scoped overrides, pre-install lock check, and installed-tree verification
remain in force. Unmanaged packages keep npm's ordinary strategy.

The synthetic host fixtures now recognize the audited Podman `6.2.0`
information schema without dropping private-store identity checks. The focused
V2-only lifecycle and global-vault profiles and source-bound history/recovery
runners are maintainer validation tools, not new runtime commands or a broadened
compatibility promise. See [testing](../testing.md).

## Choose compatible options

- **Browser:** native one-use links grant access to the private workspace
  service over `127.0.0.1`. Keep them private and close the foreground web
  command when finished. Named sign-in, LAN binding, HTTPS and CA setup are
  deferred. The full Studio mockup is an [offline design demo](../mockups/README.md),
  not part of the live layout.
- **Native version:** verified web-tab reporting is eligible on canonical stable
  OpenCode `2.x.y` releases when the native contracts match. Browser
  `--attachments` retains its distinct `2.2.6`/`2.3.0` profile. The live
  `2.4.1` pairing/layout results do not extend that profile, sharing, or
  history recovery to other versions.
- **Optional dependencies:** install the `tui` extra for `oc-box tui` and
  the independent `vault` extra when needed. `oc-box upgrade --tui` adds
  dashboard support on a supporting saved channel; `--stable` or `--devel`
  selects a different channel deliberately. Older stable `1.6` lacks the
  dashboard. The legacy OpenCode CLI does not gain 2.x client features merely
  because the oc-box package is upgraded.
- **Host importing:** qualifying pathname pastes request an import on
  supported native TUIs unless you disable host drops. Ctrl+Y desktop
  clipboard importing is a separate, saved opt-in. A verified fresh GitHub
  **development** bootstrap can enable the Ctrl-click default; that default
  is not created by a stable or ordinary PyPI install, upgrade, or restore.
  The explicit per-client option and saved workspace preference remain available
  on compatible installations. See [host-file safeguards](../guides/host-files.md).

See [installation](../installation.md) for a supported stable first install,
both optional extras, and older-launcher upgrades. Choosing a new oc-box
series does not require a workspace reset or a history reimport.
