      Set up HTTPS for named users
      
    
      One certificate per web origin, not per user. Real setup uses the host’s oc-box web commands. This preview does not install trust or change any files.
      
    
      
      
      
      
    
      
    
      
      
      oc-box web tls setup localhost (proposed)
      
      
      Use an existing trusted certificate or create one with mkcert. Stay loopback-only. Any trust-store change must be approved on the host.
      
      
      
        
        
      
      
      
      
        
      oc-box doctor --feature web-tls-local
      oc-box web tls check localhost (proposed)
      
        
      Example only: mkcert found · certificate not configured · browser trust unverified. This check installs nothing.
      
      
      
      
      
        
      Review which trust store would change, then verify the result in your browser. Nothing is installed by this demo.
      
        
      
      
      
      
      
    
      
    
      
      
      Private CA: supply a chain and key for the private hostname or IP. Client devices trust the CA’s public certificate; its private key is never distributed.
      
      
      Let’s Encrypt: use DNS-01 for a hostname under a domain you control. LAN DNS can point that hostname to a private IP. No inbound internet port is required, and clients open the certified hostname.
      
    
      
    
      
      
      Use a hostname you control and an existing public certificate, or provision one with an ACME tool such as Certbot or Caddy. A DNS challenge can work even for a LAN-only service.
